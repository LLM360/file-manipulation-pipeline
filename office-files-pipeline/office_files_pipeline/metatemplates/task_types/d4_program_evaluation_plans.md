# Program & Evaluation Plans

**Macro Category:** D — Strategic & Advisory Document Authoring
**Pattern ID:** D4

## 1. Pattern Description

The worker produces a multi-section formal document that establishes the objectives, methodology, structure, accountability, and timeline for an organizational program — either a new program being proposed, a program being formally documented for institutional use, or an evaluation framework for an existing program's outcomes. The cognitive core is program design: defining what the program does, how it will be measured or operationalized, who is responsible for what, and how the organization will know if it succeeded. What distinguishes this pattern from SOPs (C1) is that D4 documents are program-level, not process-level — they define purposes, frameworks, and accountability across time, not step-by-step operating instructions. What distinguishes it from contracts (D5) is that D4 documents are internally or inter-organizationally collaborative rather than transactional. Reference files, when present, are background content documents, organizational data (org charts, FTE reports, budget data), or formal structural outlines; web research for evidence-based instruments is common.

### Generalizable Work Context
A government agency manager, nonprofit director, public health official, or municipal department head is tasked with formalizing a new program or evaluation framework for institutional use. The trigger is typically a budget planning cycle, a program launch, a funder requirement, or a leadership directive to document and standardize. The document must satisfy multiple stakeholders — an approving executive (director, CPO, city attorney), implementing staff, and sometimes external partners. Multiple deliverable components are common: a primary narrative document plus supporting files (org charts, FTE tables, linked appendices, exhibits, separate application forms). The document must be comprehensive enough to operationalize the program without requiring verbal clarification.

## 3. Prompt Construction Template

### Persona Pattern
Assign a senior manager or director role in a government, nonprofit, or public health organization: Administrative Services Manager, Director of Family Well-Being Programs, Senior Advisor for Workforce Equity, Director of Parks and Recreation. Include the organizational context — the branch/division/department, the reporting relationship, and the stakeholder landscape (who must approve, who will implement, which partner organizations are involved). The persona should be at a level where they have authority to design the program structure but require executive or legal approval before rollout.

### Scenario Pattern
Establish a concrete program need: a budget planning mandate requiring FTE reductions, a new program evaluation plan for a grant-funded social service initiative, a formalized mentorship program guide for a government division, or an inter-organizational agreement to operationalize a health and wellness program. Include the audience for the document (approving executive, city attorney review, implementing staff, external partner). Specify named reference documents attached (background content, budget principles, org chart, contract outline, official legal language boilerplate). Provide key parameters inline: program duration, population served, required instruments, percentage reduction targets, scheduling minimums.

### Instruction Pattern
Specify the primary deliverable (Word document, multi-format package) and all named sections with explicit headers. For evaluation plans: program overview, evaluation framework (formative/summative), data collection methods, analysis approach, and appendix of instruments. For government budget packages: org chart (PDF), FTE report update (Excel), and briefing note (Word). For program guides: professional introduction, purpose/goals, eligibility, application process, matching procedures, roles, requirements, training, documentation, and timeline. For inter-organizational agreements: named articles, boilerplate sections, exhibits, and signatory information. Make secondary deliverables (linked forms, separate applications, exhibits) explicitly specified with their own format and content requirements.

### Constraint Injection Points
- **Multi-format deliverable package:** number and types of separate files (PDF org chart + Excel FTE report + Word briefing note; primary guide + linked Word forms; Word agreement + incorporated exhibits)
- **Percentage/financial calculations:** minimum FTE reduction percentage, proportional reduction logic tied to specific changes in organizational scope
- **Evidence-based instrument requirements:** named validated instruments (e.g., standardized clinical or psychometric screening tools) that must be included or cited; population-specific considerations
- **Timeline structure:** program duration (e.g., a multi-year agreement with renewal options, or a multi-month program cycle); monthly milestone timeline
- **Branding and style compliance:** organizational logo and style guide must be followed; a named external program or model credited as inspiration
- **Legal drafting standards:** attorney-review-ready language; specific boilerplate sections from attached official language document; named signatories across organizations
- **Structural compliance:** must follow named articles from attached contract outline; specific section sequence that cannot be reordered

## 4. Reference File Requirements

### File Types Needed
- **Background content document (DOCX):** Draft or background program content for the guide or plan — serves as source material to synthesize and transform into the formal document; may include organizational logo for branding compliance
- **Organizational chart (PDF):** Visual hierarchy of positions with FTE counts — source for reduction planning and cross-referencing with HR data
- **FTE report (XLSX):** Tabular HR data with position titles and current FTE counts — source for reduction calculations and for updating with planned changes
- **Budget planning principles (PDF):** Policy document with numbered principles and guidance text — provides the compliance framework for budget reduction narrative
- **Contract outline (DOCX):** Structural scaffold for an inter-organizational agreement — articles, subsections, contacts, and exhibits that the full agreement must follow
- **Official legal language boilerplate (DOCX):** Standard city or institutional contract language for specific contract sections (Miscellaneous) — must be incorporated verbatim or near-verbatim
- **Facility description (DOCX):** Space inventory and description document listing available rooms and amenities — grounds space allocation terms in the agreement

### Data Characteristics
Organizational data: position titles, FTE counts, hierarchical structure (division → branch → supervisor → position), attrition reasons (retirement, leave, resignation, vacancy). Budget principles: numbered principles with associated guidance text, particularly any named priority principle. Contract documents: article numbering, subsection headings, contact information for named individuals at both organizations, exhibit identifiers. FTE reduction data: specific named positions with specific attrition reasons and proposed reduction counts. Program parameters: scheduling minimums (hours per week, days, time of day), term duration, renewal options, financial contributions per party.

### File Complexity Spectrum
- **Minimal:** No reference files — evaluation plan or program guide drawn from web-sourced validated instruments and domain knowledge; all parameters provided inline or via URLs
- **Moderate:** One or two reference files (background content document + branding asset; or org chart + FTE report) requiring synthesis into a primary deliverable
- **Complex:** Three reference files of different types (contract outline + boilerplate legal language + facility description), each contributing a distinct layer (structure, legal text, content details) that must be integrated into a single coherent formal agreement; multiple linked secondary deliverables

## 5. Output Specification

### Primary Deliverable
- **Format:** Word document (most common); may include PDF org chart in multi-format packages
- **Structure:** Multi-section with named headers; may include a monthly or phased timeline, appendices with linked documents or cited instruments, and embedded tables (FTE counts, scheduling parameters, signatory blocks)
- **Key quality signals:** Sections are coherent with each other and consistent with reference file content (no contradictions between org chart and briefing note, between contract outline and agreement text, between background document and guide content); calculations are accurate (FTE reduction percentages verified against headcount); language is appropriate to the document's legal or administrative formality; secondary deliverables are structurally complete and linked correctly

### Secondary Deliverables (if any)
- Updated Excel FTE report (for government budget packages)
- Revised organizational chart PDF (for government budget packages)
- Separate linked Word application forms (mentor/mentee applications, roadmap templates, evaluation forms) for workforce development guides

### Gold Output Characteristics
A gold output integrates all reference file content faithfully — the org chart positions match the FTE report positions match the briefing note narrative; the contract articles follow the prescribed structural outline; the evaluation plan's appendix instruments match the stated data collection methods. Calculations are correct and transparent: if a minimum FTE reduction percentage is required, the calculation is shown and the chosen positions produce at least that reduction. For evaluation plans, the instrument section directly corresponds to the methods section — every method has an associated instrument. For program guides, the timeline spans the correct program duration with milestones that are logically sequenced. All named signatories, contacts, and named parties appear correctly in the right sections.

## 6. Complexity Knobs

| Knob | Easy | Medium | Hard |
|------|------|--------|------|
| Deliverable count | Single document | Two documents (primary guide + one supporting form) | Multi-format package: 3+ documents of different types (org chart PDF + Excel FTE report + Word briefing note; or primary guide + linked application forms + evaluation instruments) |
| Reference file count | No reference files or 1 background document | Two reference files of the same type | Three reference files of different types each contributing a distinct layer |
| Calculation requirement | No numerical calculations | One percentage calculation (FTE reduction minimum) | Multi-step proportional calculations (office count reduction → position reduction → FTE percentage verification) |
| Legal/institutional formality | Informal program proposal | Structured program guide with organizational branding compliance | Attorney-review-ready inter-organizational agreement with boilerplate official language, mutual indemnification, and insurance provisions |
| Evidence-base requirement | Domain knowledge only | One named validated instrument to incorporate | Multiple validated instruments to research, select, adapt, and cite from external academic/clinical sources |
| Timeline complexity | Static; no milestone structure | Linear milestone list | Monthly milestone timeline spanning a multi-month program cycle with distinct phases |

## 7. Boundary Cases & Adjacent Patterns

- **vs. D5 (Legal & Transactional Documents):** D4 inter-organizational agreements sit at the boundary — they have legal language and signatories, but their purpose is to define program structure rather than transfer value or rights. If the document's primary purpose is executing a real estate transaction, commissioning services, or creating a legal trust, it is D5. If the primary purpose is operationalizing a collaborative program with defined roles and accountability, it is D4.
- **vs. C1 (Standard Operating Procedure):** C1 SOPs define step-by-step procedures for operational execution; D4 plans define program objectives, frameworks, and accountability structures at a higher level. If the document is a detailed process flowchart with step owners and timelines for one operational process, it is C1. If it is a comprehensive framework document governing a multi-month program with multiple stakeholder roles, it is D4.
- **vs. E1 (Literature Review & Evidence Synthesis):** D4 evaluation plans often incorporate validated instruments sourced via web research, creating overlap with E1. The distinction is the primary output: if the deliverable is a research synthesis document (structured review of literature, study findings), it is E1. If the deliverable is a program plan or evaluation framework that cites instruments as components, it is D4.
- **Choose D4 when:** The deliverable defines the structure, methodology, and accountability of an organizational program (not just a single process); multiple stakeholders have defined roles; the document will govern a period of time (program duration, mentorship cycle, budget year); secondary deliverables (forms, FTE updates, exhibits) are tied to the primary program document.
